# ROS 2とACTで、学習と実行をつなぐ

CRANE+ V2のお辞儀動作を題材に、データ収集からGPU学習、実際のGazeboでの動作評価まで実装したプロジェクトです。指定教材の設定を基準に、前処理・追加学習・初期姿勢の多様化・実行方法を比較します。提出済みのMuJoCo搬送ロボットとは別の成果物です。IDは141960です。

## 実測結果

初回はGoogle ColabのTesla T4で6モデルを学習し、実行方法を含めた9設定を比較しました。初回の重みと生軌跡は保存待機中のタイムアウトで失われましたが、集計はDriveから保全しています。今回は選択設定を固定して基準・選択モデルを再学習し、新しい50条件（seed 4000〜4049）で測定しました。設定は `diverse_2000`, `n_action_steps=1`, `ensemble=0.01` です。

**未使用の50条件で、成功数は基準モデル 33/50 → 選択したACT 50/50でした。** 同じ初期条件の組で改善17件、悪化0件。McNemarの正確検定（両側）はp=1.52588e-05です。

| 最終評価 | 成功数 | 成功率の95% Wilson区間 | 実行エラー |
|---|---:|---:|---:|
| 基準モデル | 33/50 | 52.2〜77.6% | 0 |
| 選択ACT | 50/50 | 92.9〜100.0% | 0 |

| 比較した設定 | 検証成功数 | 終端RMSE [rad] |
|---|---:|---:|
| `lesson_baseline` | 10/20 | 0.02126 |
| `diverse_2000` | 20/20 | 0.00156 |

上の表は再実行の確認用20条件です。設定は初回の検証で成功数、次に終端の平均関節RMSEで選びました。再実行では学習前にその設定を固定し、最終評価前に新しいチェックポイントのSHA-256を保存しました。結果に基づく再調整は行っていません。

## 工夫と、比較から分かったこと

- **データを状態の範囲で増やす**：固定姿勢の20記録に、腕の初期角度を各軸±0.08 radで変えた60記録を追加しました。人の実演ではなく、Gazeboで動かして実際の関節状態を記録したスクリプト実演です。基本データの第3関節の指令は0.05 radずつ12回。多様化した記録は、初期姿勢から同じ目標まで12分割して進めます。
- **時刻と末尾データの扱いを明示する**：教材の過去から始まる動作列と、現在から50 ms刻みの列を比較。未来の観測・欠測を拒否し、短い記録を実データとして最長まで埋めない方式を用意しました。
- **推論までつないで測定する**：学習損失だけで選ばず、ROS 2の指令で実際にロボットを動かし、到達・停止・滑らかさ・推論時間・制限への介入を測定しました。
- **評価用のデータを分ける**：エピソード単位で分割し、学習0～79、検証1000～1019、初回の最終確認2000～2049、再実行の最終確認4000～4049のseedを使います。比較は同じ初期条件の組で行います。失敗も実行エラーも成功率の分母から除きません。

追加学習だけでは改善しきれませんでした。固定姿勢だけのデータでは、第1関節の標準偏差が約1.14e-13 radしかなく、少し異なる初期姿勢が正規化後に極端な値になります。多様化した記録では約0.0218 radでした。いずれも再収集データでの診断値です。この違いは入力分布のずれを示す手掛かりですが、データ量と多様性を同時に変えているため、改善を一つの原因に断定しません。

実測されたJointStateの関節順は教材の推論側と一致していました。関節名による明示的な整列は実装しましたが、この実験を「関節順バグの修正」とは呼びません。順序を変えると入力と初期重みの対応も変わるため、単一の学習seedの差を一般化できません。

## 課題と評価条件

目標は腕の第3関節0.60 rad、他の腕関節0 rad、グリッパー-0.5236 radです。8シミュレーション秒以内に、全5関節の誤差0.05 rad以下、最大関節速度0.10 rad/s以下を0.5秒保ったら成功です。

全方式で同じ関節制限ガードとリセット条件を使います。目標姿勢を直接与える課題専用制御も検証し、20/20回成功しました。単一の既知目標では学習なしの制御も有効であり、ACTが常に必要という結論ではありません。

## 再実行

1. `PAI_ROS2_ACT_replication_141960.ipynb` をGoogle Colabで開き、新しい空のGPUランタイムを選択します。
2. 上から実行します。初回のROS 2環境構築は時間がかかります。Ubuntu 22.04の実行環境をColab本体から分離し、ROS 2 HumbleとIgnition Gazebo Fortressを使います。
3. データ収集、固定した2モデルのGPU学習、20条件の再確認、新しい50条件の評価、統計集計、ZIP保存を順に実行します。
4. 完了したら証拠記録ZIPとチェックポイントZIPを保存してください。ランタイムを終了すると `/content` 内は失われます。

ノートブックはソースから生成した再現用です。事前出力を実行結果のように見せてはいません。実際の今回の実行は下記Colabで行い、ログと全軌跡を証拠記録ZIPへ保存しました。再実行用ノートブックの各工程は、新しい空のランタイムから実行して確認しました。

学習済みモデルの再利用では、重みだけでなく `selected_policy.json` の実行設定も使ってください。時間方向の平均化は学習時のチェックポイント設定に含まれず、`policy_service.py` の `/load` に `trial`, `n_action_steps`, `ensemble` を渡して適用します。サービスはループバック127.0.0.1でのみ待ち受けます。

## 教材との対応と限界

モデル構造・学習率・200 step/batch 2の基準設定・関節順・時刻とパディングの規則を参照しました。元の人手収集rosbagは提供されていないため、独自のGazebo記録JSONとメモリ上のデータローダーを使っています。教材の実験結果そのものやrosbag→LeRobot形式変換の完全再現ではありません。

観測は5関節角とその複製です。画像・言語入力のVLAではありません。固定目標、限定した初期姿勢、1つの学習seedでの比較です。実機、把持、未知目標、広い初期姿勢、複数の学習seedでの再現性は未検証です。「比較した条件の中での最良」であり、全てのモデル・課題での最適性は主張しません。
